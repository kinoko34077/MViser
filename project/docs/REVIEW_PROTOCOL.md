# Review protocol (machine-verifiable evidence)

Source: MViser#38, kinotch-repo-monitor#29, ADR 0005.

## Run
```
python project/tools/run_mviser.py audit --out output/audit            # all checks, --gui auto
xvfb-run -a python project/tools/run_mviser.py audit --gui on          # Linux headless, GUI mandatory
python project/tools/run_mviser.py audit --only jp-font,av-sync        # subset
```
Exit code 1 on any FAIL. CI: workflow **MViser audit** → artifact `mviser-audit-<os>`.

## Answer format (every review / verification reply)
1. **SHA** — commit audited (`sha` in the report)
2. **Command / mode** — exact command, `--gui` mode, OS
3. **Summary** — PASS/WARN/FAIL counts
4. **Key values** — measured numbers from `checks[].values` (offsets, ratios, counts)
5. **Artifacts** — CI run + artifact name, or local path
6. **Residual boundary** — every WARN `boundary`, verbatim
7. **Conclusion** — `PASS` / `PASS WITH NON-BLOCKING BOUNDARY` / `FAIL — follow-up required`

## Rules
- Never hand a machine-verifiable check back to a human; add or extend an audit check instead.
- Screenshots are supplementary; the verdict comes from measured values.
- A FAIL gets its own issue; do not loosen a rule to make it pass. Rules live in `checks[].rule`.
- Only the `boundary` items stay in #14 (generated by `project/tools/manual_check.py --markdown`).
